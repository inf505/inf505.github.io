# Open Issues — County-Confederal System

**Purpose**: The stress-test queue after Change Sets 1–11. Each entry is a problem the corpus does not yet resolve, with a severity, the level that owns it, and a concrete test that would validate or falsify the design.

**Companion files**: `changelog.md` (what changed — Change Sets 1–11). The subsystem ID registry lives in `README.md` (Meta). This file tracks what is still _unproven_.

**Status**: `OPEN` = unresolved; `MITIGATED` = a partial mechanism exists but is not stress-tested; `DEFERRED` = intentionally left open; `RESOLVED` = closed by an edit or a test result.

**Severity**: `CRITICAL` = could break the design; `HIGH` = load-bearing but tractable; `MEDIUM` = policy/operational; `LOW` = edge case.

**Owner**: County / State / Compact / Confederation / Cross-level.

**How to use**: Pick a scenario, run the test, record the result. Do not mark an issue `RESOLVED` without a test result or an explicit design decision.

## G. Intentional trade-offs (not bugs)

These are load-bearing choices. They should not be "fixed" without a deliberate redesign.

| Trade-off                              | Why intentional                                | Residual risk                                        |
| -------------------------------------- | ---------------------------------------------- | ---------------------------------------------------- |
| **No central bank**                    | Prevents inflation and monetary centralization | No lender of last resort; deeper recessions          |
| **No standing army**                   | Prevents a permanent war machine               | Slow mobilization; fragile deterrence                |
| **No federal police**                  | Prevents a national police state               | Cross-county enforcement depends on compacts         |
| **No income tax**                      | Prevents a federal fiscal leviathan            | Less redistribution; state/county revenue volatility |
| **No federal agencies**                | Prevents regulatory capture at the center      | Coordination gaps; county capacity strain            |
| **Slow war powers**                    | Prevents unilateral war                        | Surprise-attack response is slow                     |
| **Fragile nuclear deterrent**          | Prevents accidental launch                     | Crisis instability; slow retaliation                 |
| **County sovereignty over uniformity** | Exit and accountability                        | Fragmentation; cross-county spillovers               |
| **Exit over voice**                    | Secession as the ultimate check                | Secession crises; boundary disputes                  |
| **No permanent center**                | Prevents a successor regime                    | Re-centralization risk; "use it or lose it"          |

## H. Recommended stress-test scenarios

Run these in order. Each should produce a written result and, if needed, a new change set.

1. **Pandemic + cyberattack + secession** — the corpus's own suggested scenario. Tests public health, cyber compacts, county veto, interposition, and secession at once.
2. **Upstream opt-out pollution** — an opt-out county discharges into a downstream county; downstream sues; no compact member is available. Tests OI-01.
3. **Land-value crash** — LVT revenue falls 30%; state reimbursement, Guard, and courts are stressed. Tests OI-03 and OI-10 (seniority/lapse is now the defined shedding mechanism).
4. **Surprise attack + nuclear consent** — tests OI-23 and OI-24.
5. **County insolvency** — a pension trust or mutual fails. Tests OI-15.
6. **Transition Day 1** — 12M personnel, 150k prisoners, all county charters, 640M acres. Tests OI-27, OI-28, OI-29.

## J. How to close an issue

1. **Run the test.** Record the scenario, assumptions, and result in a new section of this file.
2. **Decide.** Either accept the result as a trade-off, or propose a change set in `changelog.md`.
3. **Apply and log.** If a change is made, add it to `changelog.md` with the issue ID.
4. **Mark status.** `RESOLVED` only with a test result or an explicit design decision. `DEFERRED` is a legitimate outcome; `OPEN` is not a failure.

**When adding a new subsystem** (design-quality checklist, carried over from the retired gap registry):

- [ ] Design document created
- [ ] Integrates with existing files (cross-references)
- [ ] No "magic" — every function assigned to a level (county/state/compact/Confederation)
- [ ] Funding sourced in `public-finance.md`
- [ ] Personnel sourced (sortition, election, appointment, market)
- [ ] Accountability mechanism (recall, liability, audit, sunset)
- [ ] Exit/opt-out path for counties/states/individuals
